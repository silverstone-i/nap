# 0013 — Standard resource routes

- **Status:** Accepted
- **Date:** 2026-08-07

## Context

Every PRD that defines an API needs to say what its routers do, and PRD
0003's route-demand requirements already name routes (`getWhere`,
`bulk-update`, …) that no accepted document defines. Without a fixed
contract, each PRD would re-enumerate the same CRUD mechanics and drift
from the others. This ADR fixes the standard route set; the per-route
reference lives in
[RULES/api-standard-routes.md](../RULES/api-standard-routes.md).

## Decision

1. **Every resource router is generated by `createRouter`** (the
   framework layer, ADR-0001) and mounts at `/api/<module>/v1/<router>`.
2. **The standard set is thirteen routes**, each individually
   disableable at the call site:

   | Route       | Method and path    | Demands  |
   | ----------- | ------------------ | -------- |
   | create      | POST /             | `full`   |
   | getById     | GET /:id           | `view`   |
   | getWhere    | GET /              | `view`   |
   | archived    | GET /archived      | `view`   |
   | update      | PUT /:id           | `update` |
   | bulk-insert | POST /bulk         | `full`   |
   | bulk-update | PUT /bulk          | `update` |
   | archive     | DELETE /:id (soft) | `full`   |
   | restore     | POST /:id/restore  | `full`   |
   | import-xls  | POST /import       | `full`   |
   | export-xls  | GET /export        | `view`   |
   | ping        | GET /ping          | `view`   |

3. **Custom routes are declared before the factory** so they match
   first; each carries its own permission in `module::router::action`
   notation.
4. **Every route runs the RBAC middleware; mutations additionally get
   audit-field injection.** No route generated by the factory is
   ungated.

## Consequences

- A PRD's API section names its routers and documents only custom
  actions; "standard CRUD" means exactly this table.
- The demand column is the binding form of PRD 0003's route-demand
  requirement; the PRD cites this ADR rather than carrying its own
  route list.
- `archive` is a soft delete — the factory generates no hard-delete
  route. Destructive removal, where a module ever needs it, is a
  custom route with its own ADR-worthy justification.

## Alternatives considered

**Bespoke routes per module.** Rejected. Thirteen decisions re-made per
resource, inconsistent paths and demands across modules, and no way for
a PRD to say "standard CRUD" and mean something precise.

**A lean set, grown when needed.** Rejected. Every later addition would
ripple through each PRD that referenced the set by name; the full set
with per-route disable flags gives the same minimalism per router
without renaming churn.
