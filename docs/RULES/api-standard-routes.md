# RULES — Standard resource routes

Governs the `createRouter` factory in `apps/api/src/framework/` and every
router generated by it. _(applies when `createRouter` lands; the contract
is fixed now by [ADR-0013](../ADRs/0013-standard-resource-routes.md) so
PRDs can reference it.)_

## The contract

Every resource router mounts at `/api/<module>/v1/<router>` and gets the
thirteen standard routes below. "Standard CRUD" in a PRD's API table
means exactly this set. A PRD documents only its custom actions and any
disabled routes.

| Route       | Method and path   | Demands  | Notes                                                                   |
| ----------- | ----------------- | -------- | ----------------------------------------------------------------------- |
| create      | POST /            | `full`   | Audit fields injected.                                                  |
| getById     | GET /:id          | `view`   |                                                                         |
| getWhere    | GET /             | `view`   | Filterable list; scope and status predicates applied per ADR-0008.      |
| archived    | GET /archived     | `view`   | Archived rows only.                                                     |
| update      | PUT /:id          | `update` | Audit fields injected.                                                  |
| bulk-insert | POST /bulk        | `full`   | Audit fields injected.                                                  |
| bulk-update | PUT /bulk         | `update` | Audit fields injected.                                                  |
| archive     | DELETE /:id       | `full`   | Soft delete. No hard-delete route exists in the standard set.           |
| restore     | POST /:id/restore | `full`   |                                                                         |
| import-xls  | POST /import      | `full`   | Audit fields injected.                                                  |
| export-xls  | GET /export       | `view`   | Export honors the caller's scope and status filters — never a raw dump. |
| ping        | GET /ping         | `view`   | Router liveness.                                                        |

## Rules

- Each route has a disable flag at the `createRouter` call site.
  Disabling is per router, never per role — role-level restriction is
  RBAC's job, not the factory's.
- Custom routes are declared before the factory call so Express matches
  them first. Each custom route names its permission as
  `module::router::action`; the action must exist in `cell_catalog`.
- Every generated route runs the RBAC middleware. Mutating routes
  (create, update, bulk-insert, bulk-update, archive, restore,
  import-xls) additionally run audit-field injection.
- Route demands are fixed by ADR-0013. A router that needs a different
  demand for a standard operation is a design smell — split the
  resource instead (ADR-0010).
